## Coverage

The combined fixtures and supporting tests cover the following categories;
they are not all real cross-process event scenarios in the current matrix:

- multiple sessions and two parallel subagents;
- delegation grant, deny/timeout handling and child lineage;
- subagent progress, text, thinking, success and failure;
- tool generation, start, progress and completion;
- plan, artifact, approval and clarification facts;
- heartbeat, context continuation, provider retry and usage visibility;
- replay, duplicate/idempotency, out-of-order delivery, lease takeover and
  stale-epoch rejection;
- terminal completion, failure, cancellation and late-event fencing.

The canonical contract fixture at
`tests/fixtures/events/process-tree-fixture.json` is parsed and reduced by the
actual web2 parser, semantic reducer and process reducer, then rendered through
`MessageBubble`. The exported frontend ledger equals the fixture and preserves the common
`parent_turn_id`, allocation IDs, child sessions, tool invocation IDs and
artifact parent links without relying on arrival order or assistant text.

## Loss and rename policy

The contract forbids silently renaming or discarding canonical events. Go transport keeps the
raw envelope; web2 either projects a known fact or records the event in the
controlled `unknownEvents` bucket. The consumer report and combination ledger
provide catalog evidence. They do not substitute for the required runtime
loss/downgrade/rename report.

## Durable child authority increment (2026-09-27)

child run and child turn before forwarding grant/start events. Atomic predicates
reject conflicting allocations and identities; replayed grants preserve an existing
child start. Reads and writes bind tenant, parent session/run/turn and execution
epoch, with the current lease epoch fencing old authority. Session deletion already
cascades admission records. No transcript or canonical-event copy is introduced.
